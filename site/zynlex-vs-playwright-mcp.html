ZYNLEX vs Playwright MCP

Both give a coding agent a browser to check its work. We gave Claude Code the same bugs with each one, three runs per bug. Both fixed every run. ZYNLEX did it with about a third of the tokens.

Why the gap

Turns cost more than replies. Claude Code sends its whole conversation again on every turn, so most of a run’s tokens are the same context re-read. A run of 8 turns is cheap; a run of 20 isn’t, even when each browser reply is short.

One script instead of one action per call. ZYNLEX’s script tool takes a few lines of Playwright-style code: open the page, do every step, return just what the agent needs to see. Playwright MCP can run code too, but in these runs agents stepped through it one action at a time, as its tool list invites.

await page.goto('http://run9313.localhost:9313/#/event/2');
await page.waitForTimeout(500);
await page.fill('#comment-text', 'Testing comment bug');
const [resp] = await Promise.all([
  page.waitForResponse(r => r.url().includes('/comment')),
  page.click('#post-comment'),
]);
const status = resp.status();
const url = resp.url();
await page.waitForTimeout(300);
const comments = await page.locator('#comments li').allTextContents();
return { status, url, comments };

The agent’s first call in the comments run, as it sent it. It returned the 404 and the URL it went to, which is the bug.

The same window, every time. ZYNLEX runs in the window you have open, and the agent’s script can be run again unchanged after a fix. You can watch every step, flag an element with Ctrl+Shift+E and it reaches the agent as a note, or pause it and take over.

Which one to use

ZYNLEX
  • You’re on Windows 10 or 11, building a web app on localhost
  • You want to see what the agent does, point at bugs and take over
  • Token cost matters: about a third of Playwright MCP’s here
  • You also want a dev browser: network log, mocks without a proxy, device sizes, an API client
Playwright MCP
  • You’re on macOS or Linux
  • The agent runs in CI or headless, with no one watching
  • You need Firefox or WebKit, not just Chromium
  • You want Microsoft’s project and the wider Playwright ecosystem

How we measured, and the limits

Each run starts a fresh copy of a small web app with one planted bug. Headless Claude Code (claude -p, Sonnet) gets the bug report, file tools and exactly one browser tool. A separate grader checks the fix in Edge and marks it pass or fail. Tokens are every input token of the run, cache reads included.

  • Our harness, our bugs, one machine, one model. That’s why everything is public to rerun.
  • ZYNLEX ran in a real window, the others headless, so time isn’t a fair comparison; tokens and cost are.
  • The 176k build was made with these bugs in view. The blind build, 222k, hadn’t seen them.
